# PeopleSphere: Enterprise Employee Lifecycle Platform (Salesforce)

A 100% Salesforce-native HR platform: Apex, Lightning Web Components, custom objects and Experience Cloud.
It covers the full employee journey, from hiring to onboarding, learning, performance, attendance, service desk, exit and analytics.

- **Org:** `orgfarm-f91af49989-dev-ed` (CLI alias `peoplesphere`)

- **Public HR Admin demo (password):** https://orgfarm-f91af49989-dev-ed.develop.my.site.com/peoplesphere/s/hr-admin

## Deploy to any org

Prerequisites: Node 18+, then `npm install -g @salesforce/cli`.

```bash
sf org login web --alias peoplesphere --instance-url https://YOUR-DOMAIN.my.salesforce.com
```

```bash
sf project deploy start --target-org peoplesphere -d force-app --test-level RunLocalTests --wait 40
```

```bash
sf org assign permset --name PeopleSphere_Admin --target-org peoplesphere
```

Load the sample data (fictional company "Nimbus Technologies", 40+ employees). Run the three scripts in order:

```bash
sf apex run --file scripts/apex/seed1_organization.apex --target-org peoplesphere
```

```bash
sf apex run --file scripts/apex/seed2_learning_policy.apex --target-org peoplesphere
```

```bash
sf apex run --file scripts/apex/seed3_operations.apex --target-org peoplesphere
```

The running user is linked to the "Engineering Manager" employee, so My Workspace and Manager Workspace both have data.

Schedule the nightly automation (Developer Console → Execute Anonymous):

```apex
PS_DailyJob.scheduleDaily();
```

### Changing the data model
Edit the `SCHEMA` list in `tools/generate_metadata.py`, then regenerate objects, fields, layouts, tabs and permission sets:

```bash
python tools/generate_metadata.py
```

New Apex classes or triggers need a `-meta.xml`. To create any that are missing:

```bash
sh tools/meta.sh
```

## Public demo site (Experience Cloud)

The site lets anyone use the app without logging in, as the fictional employee **Alex Demo**.

**How it is secured:**
- Site guests have no record access in Salesforce. The guest user's only permission set is `PeopleSphere_Guest_Demo`, which grants a single class, `PS_GuestGateway`.
- `PS_GuestGateway` rejects anyone who is not the site guest. It runs the normal controllers (declared `inherited sharing`) on behalf of the demo employee only.
- It blocks opening other people's 360 profiles, the attrition-risk and ticket-list reports, task completion for others, and resignation.
- The components detect `@salesforce/user/isGuest` and switch to the gateway automatically.
- Salaries, attrition risk, the HR dashboard and the manager workspace are **not** exposed.

> ⚠️ Anyone with the link can read the demo data and create leave requests, tickets, kudos and so on. **Never load real employee data into this org.** To take the site down: Setup → Digital Experiences → All Sites → PeopleSphere → Administration → Deactivate.

To rebuild the site in another org:

```bash
sf community create --name "PeopleSphere" --template-name "Build Your Own" --url-path-prefix peoplesphere --target-org peoplesphere
```

Then do the following:
1. Retrieve and deploy `experiences/PeopleSphere1` and `networks/PeopleSphere.network-meta.xml`. These set `isAvailableToGuests: true`, put `c:psPublicDemo` on the home page and set status `Live`.
2. Assign `PeopleSphere_Guest_Demo` to the site's guest user (`SELECT GuestUserId FROM Site WHERE Name = 'PeopleSphere'`).
3. Create the demo employee:

```bash
sf apex run --file scripts/apex/setup_public_demo.apex --target-org peoplesphere
```

4. Publish the site:

```bash
sf community publish --name PeopleSphere --target-org peoplesphere
```

## HR Admin Console

`psHrConsole` puts every HR feature on one page: the dashboard, any employee's 360 view (with pay), onboarding management and document verification, organization-wide approvals and reviews, the service desk (`psServiceDesk`), the recruitment board (`psRecruitment`, where Hire creates the employee and starts onboarding), the full HR Assistant, the org chart and **All records** (`psDataExplorer`): create, view, edit and delete any record of all 35 PeopleSphere objects.

**Record editor** (`PS_RecordEditorController` + `psRecordForm`, `psRecordView`, `psLookupField`, `psRecordApi`):
- Forms are generated from the live schema: text, numbers, dates, date-times, checkboxes, picklists, long text and lookup search (including users).
- Required fields are enforced. Calculated, auto-number and system fields are read-only.
- The record view shows every field, plus related lists. Each list has a **+** to create a child record that is already linked to the parent, and you can click through to any linked record (with Back).
- Saves go through the normal triggers, so new employees get IDs, onboarding and training, approvals deduct balances, and so on.
- On the public HR link, every editor call goes through `PS_GuestHrGateway` and needs the password session token.
- Setup-level changes (users, permissions, new fields or objects) are not available from any public page, by Salesforce design. Use a real Salesforce login for those.

- **Inside Salesforce:** App Launcher → PeopleSphere → **HR Admin Console**. Service Desk, Recruitment Board and Data Explorer also have their own tabs. Visible to the Admin and HR permission sets.
- **Public link (password-protected):** https://orgfarm-f91af49989-dev-ed.develop.my.site.com/peoplesphere/s/hr-admin
  - The page asks for the HR password before showing anything.
  - The password is enforced on the server. `PS_GuestHrGateway.unlock(password)` compares SHA-256(password) with `PS_Demo_Setting__mdt.Default.HR_Password_Hash__c` and returns a token that is valid for 8 hours. The token is signed with HMAC-SHA256, using a key derived from the stored hash and the org id.
  - Every other gateway method rejects calls without a valid token, so calling the Apex directly doesn't bypass the password.
  - The browser keeps the token in `sessionStorage` for the tab (`c/psHrAuth`). The **Lock** button clears it.
  - Anyone who knows the password can approve, reject, hire, edit tickets and see the (fictional) salaries.

### Changing the HR demo password
Compute the new hash:

```bash
python -c "import hashlib;print(hashlib.sha256(b'NEW-PASSWORD').hexdigest())"
```

Put the result in `force-app/main/default/customMetadata/PS_Demo_Setting.Default.md-meta.xml`, then deploy it:

```bash
sf project deploy start --target-org peoplesphere -d force-app/main/default/customMetadata/PS_Demo_Setting.Default.md-meta.xml
```

Changing the password also invalidates every existing session, because the signing key changes.

## Optional: connect Claude to the HR Assistant

Without setup, the assistant answers policy questions with the most relevant policy excerpts. To get written answers from Claude, grounded in your policies:

1. Setup → **Named Credentials** → External Credentials → New: name `Claude_API_Key`, protocol **Custom**. Add a principal with an authentication parameter `ApiKey` holding your Anthropic API key. Add a custom header `x-api-key` = `{!$Credential.Claude_API_Key.ApiKey}`.
2. Named Credentials → New: name **`Claude_API`**, URL `https://api.anthropic.com`, External Credential `Claude_API_Key`, and allow formulas in headers.
3. Give the External Credential principal access through a permission set (External Credential Principal Access).

`PS_AssistantController.askClaude` calls `claude-opus-5-5` with low effort and server-side fallback. If the call errors or is refused, the assistant falls back to the excerpt answer.

## Security model (internal users)

- Sensitive objects (Employee, HR Ticket, Candidate) use Private sharing. Child records inherit from Employee.
- Each employee gets read access to their own record and their manager gets read access to the team (`PS_EmployeeHandler.syncShares`).
- Compensation fields, attrition risk and quiz answers are hidden from the Employee and Manager permission sets.
- Approvals (leave, expense, manager review) check explicitly that the caller is the approver or HR before acting.
- Automation services run `without sharing` by design and are reached only from triggers or authorised controller methods.
- Field history is tracked on Employee, HR Ticket, Exit, Performance Review and Company Asset.
